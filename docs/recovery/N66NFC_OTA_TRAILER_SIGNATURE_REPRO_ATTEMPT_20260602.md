# n66nfc OTA trailer signature reproduction (corrected 2026-06-02)

## Scope

Static-only reproduction of the n66nfc post-EOCD AP-side trailer verifier.

Safety boundary:

- no band connection;
- no Notify/NFX install click;
- no Mi Fitness/DFU `prepare`, firmware body/chunk, `validate`, `upgrade`, or recovery command;
- patched artifact, when mentioned, is `/tmp` local-only and **NOT_FOR_INSTALL**.

Helpers:

```text
tools/firmware/ota_trailer_ecdsa_probe.py
tools/firmware/make_n66nfc_sportxms_not_for_install.py
```

## Corrected verifier model

The first naive model failed because it used a linear digest:

```text
SHA256(zip[0 : file_size - 0x50])
```

Re-reading the `verify_package` hash loop showed the firmware computes a stride digest instead:

```text
padding_info_offset = file_size - 0x50
for i in range(padding_info_offset >> 20):
    sha256.update(pkg[i * 0x100000 : i * 0x100000 + 0x400])
sha256.update(pkg[(padding_info_offset >> 20) * 0x100000 : padding_info_offset])
```

Then it verifies:

```text
signature = trailer[16:80] as raw secp256k1 ECDSA(r, s)
message   = firmware_stride_sha256
pubkey    = AP-side verify_package secp256k1 public key
```

The embedded public key, present in both official `1.3.206` and `1.3.210` `vela_ap.bin`, is public verification material:

```text
Qx = 4c5ee3be1fc08452f8b7064cbec0bd13b65a9fced76acf9d87c7fba91add3dd5
Qy = 85356d12dbb8278e4b3c8b61c40b87c62ab613c1f0f69f8c21b90bde5856687e
```

## Patched old-trailer test

A local `/tmp` only `1.3.206` SportXms patch-on-copy was generated by `tools/firmware/make_n66nfc_sportxms_not_for_install.py` to test the verifier, not for installation:

```text
/tmp/miband9_sigrepro_20260602/NOT_FOR_INSTALL_miband9_13206_sportxms_20000us_old_trailer_from_tool.zip
```

Patch details:

```text
vela_ap.bin raw 0x1779bc: a0 86 01 00 (100000us) -> 20 4e 00 00 (20000us)
ota.json visible vela_ap.bin MD5 updated
old official 80-byte trailer appended
```

Verifier result:

```text
patched eocd_end: 0x29df477
patched firmware_stride_sha256: 018b0c8f6391dc06409d083e3dab2224930a3aa5503d067797a72f7b31c95db9
patched firmware stride ECDSA result: fail
linear ECDSA result: fail
```

This proves ordinary repack + visible MD5 update + old trailer copy-forward does not pass the reproduced AP-side verifier.

## ZIP coverage note

For official `1.3.206`:

```text
eocd_end: 0x29e61ab
high complete-MiB regions: 41
low20 remainder: 0xe61ab
hashed total bytes: 984491
```

The hidden signature does not cover every ZIP byte linearly. It covers:

- first `0x400` bytes at each complete MiB boundary;
- the final low-20-bit remainder, which includes late entries, central directory, and EOCD;
- excludes the final 80-byte trailer.

`vela_ap.bin` is compressed in the ZIP (`method=8`), so the raw SportXms patch offset does not map linearly to an outer ZIP byte. A normal repack changes compressed data and central-directory metadata enough to fail the stride signature.

## Safety consequence

The verifier is now reproduced for official packages, but this does **not** make patched OTA installable.

Current conservative decision:

- official packages pass hidden AP-side verifier;
- ordinary patched copy with old trailer fails;
- visible `ota.json` MD5 is insufficient;
- patched OTA remains **NOT_FOR_INSTALL** unless the live path is proven to bypass/disable `persist.verify.upgrade`, or the package can be re-signed with valid vendor material.
